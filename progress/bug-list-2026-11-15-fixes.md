# バグ一覧（2026-11-15）の修正で決めた仕様

対象は `markdown/bug-list-2026-11-15.md`。報告に修正方針が書かれていない箇所で決めたことだけを記録する。

## Decision

- **重複 ID の現在位置は「元位置の対応表」で追跡する（A3・A1）**
  - Go（`pkg/playqueue` の `origin`）と iOS（`MusicPlayerService.queueOrigins`）の両方で、シャッフル後の各要素が元の並びの何番目だったかを保持する。
  - iOS のシャッフル中の削除・追加・次に再生・並び替えも、この対応表を更新する。
- **シャッフル中の並び替えは解除時に元の順へ戻す（A1）**
  - 削除と追加は解除後も保つ。並び替えはシャッフル後の並びだけに効かせる。「解除＝元の曲順に戻す」を仕様とした。
- **既定シャッフルの読み書きは `Store.UpdateMap` に集約する（A2）**
  - ロックを保持したまま、読み込み・コピーへの変更・保存を行う。保存に失敗してもキャッシュは変わらない。
  - 既存の `Load` / `LoadMap` / `Save` の挙動は変えていない。
- **プレイリスト名変更時は、改名したプレイリスト自身の設定を優先する（A7）**
  - 新しい名前の側に残っていた既定値は、過去のプレイリストの孤児として上書きまたは削除する。
- **シャッフル指定で `startIndex` が範囲外なら停止（-1）にする（A5）**
  - 非シャッフル時の挙動に揃えた。
- **歌詞ファイルのドロップ取り込みは `.lrc` と `.txt` のみ（B6）**
  - 同名の上書きは残した（更新した歌詞の再取り込みを想定）。一時ファイル経由で置き換える。
- **`mergePlainTxtWithJa` の行数は主歌詞に合わせる（B7）**
- **同一タイムスタンプの和訳の割り当て規則（B2、Desktop と iOS 共通）**
  - 同じ時刻の和訳と主歌詞の件数が一致すれば位置で対応させる。
  - 一致しなければ、空でない和訳を空でない主歌詞へ順に割り当てる。
- **iOS の保存データが復号できないときは退避してから空で始める**
  - 退避先は `<キー>.undecodable-backup`。既存の退避は上書きしない。
- **iOS のアートワークは画像として読めるものだけキャッシュする**
  - キャッシュヒット時に復号できなければ、そのファイルを削除して再取得させる。

## Alternatives considered

- **重複 ID を「同じ ID の何番目の出現か」で対応付ける案**: 不採用。シャッフルを入れると現在曲が先頭へ移り、順位が常に 0 になるため、解除時に 1 回目の出現へ戻ってしまう。
- **`Store.LoadMap` が常にコピーを返す案**: 不採用。全ストアの呼び出し元に影響し、大きなストアで毎回コピーが発生する。

## Constraints / Gotchas

- iOS の `play(startIndex:)` は追加済みだが、画面側からは渡していない。画面の行一覧と再生キュー（ダウンロード済みの曲のみ）が一致しないため、行番号の写像が必要になる。同じ曲を 2 回入れたプレイリストで 2 回目をタップすると 1 回目から始まる問題は残っている。
- `[00:12:34]` 形式の LRC 時刻は、Desktop が「12.34 秒」、iOS の LRCParser が「時:分:秒」と解釈する。未統一。
- 見送った候補: シャッフル順列の検証（外部入力の経路がない）、`TVRelayStreamPlayer` の世代チェックと `task` の並行書き込み（TV スキームをこの Mac でビルドできない）、`WatchTransferMeta.storageStem` の衝突（転送済みファイルとの互換方針が未決定）。
