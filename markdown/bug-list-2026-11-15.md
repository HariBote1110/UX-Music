## High

### A1 iOS: シャッフル中のキュー編集が巻き戻る
- `UX-Music-Mobile/UX-Music-Mobile/Services/MusicPlayerService.swift`
- `moveQueueItem` / `removeQueueItem` / `insertNext` / `appendToQueue` は `queue` のみ変更し `originalQueue` に書かない。`setShuffleEnabled(false)` が `queue = originalQueue` で復元するため、削除曲の復活・追加曲の消失・並び替え無効化が起きる

### A2 Go: コレクション既定シャッフルの永続化が競合で壊れうる
- `server/app_collection_shuffle.go` / `internal/store/store.go`
- Set/Rename/Delete がいずれも LoadMap→変更→Save の read-modify-write で、並行更新が lost update になる。さらに store がキャッシュ済み map の実体を返すため、Save 失敗時もメモリだけ変更済みになり永続化と乖離する。同一 map への並行読み書きで fatal の可能性も

### B1 Desktop: parseLRC が表記ゆれを丸ごと捨て歌詞が空になる
- `src/renderer/js/features/lyrics-translation.ts` の `parseLRC`
- 正規表現が分2桁・小数必須・小数1桁不可のため `[0:12.34]` / `[00:12]` / `[00:12.3]` が全て空になる（node で実測）。iOS の LRCParser は許容するためプラットフォーム間不一致

## Medium

### A3 現在曲の再特定が ID 一致依存で、重複登録時に誤った出現を掴む
- `pkg/playqueue/queue.go` `SetShuffle` / `MusicPlayerService.swift` `play()`
- 同じ曲を2回入れたプレイリストで、2回目を再生/シャッフル切替すると現在位置が1回目へずれる

### A4 Desktop レガシー経路: シャッフル開始時に開始曲と同 ID の全出現を除去
- `src/renderer/js/features/playback-manager.ts` `runPlaySongWork`
- `filter(s => s.id!== songToStartWith.id)` の後に開始曲を unshift するため重複出現が消える。ID 未設定の曲は全て一致扱いでキューが1曲に崩壊しうる

### B2 mergeLrcWithJaLrc: 同一タイムスタンプの和訳は最初の1行しか生きない
- `src/renderer/js/features/lyrics-translation.ts`（Swift の LyricsTranslationMerger も同型）
- parseLRC の単調化と merge 側 timeKey の再衝突で先勝ちになる。先行行が空白だと位置フォールバックも効かず和訳が失われる

### B3 歌詞ロードに世代管理がなく、速い曲送りで前曲の歌詞が上書きしうる
- `src/renderer/js/features/lyrics-manager.ts` `loadLyricsForSong`
- 非同期結果を無条件に反映するため、曲送りが速いと前曲の歌詞が後から表示される

## Medium-Low 〜 Low

### A5 Go: SetQueueWithShuffle の startIndex 範囲外がシャッフル時だけ黙って先頭再生になる
- `pkg/playqueue/queue.go` `setQueueLocked`（非シャッフル分岐は -1＝停止で非対称）

### A6 TS キャッシュ（collection-shuffle.ts）の競合・例外伝播
- load 完了時の Map 全置換が、load 中に完了した set を上書きしうる。バインディング未初期化時は空 Map に置換（Set 側は throw で非対称）。`notifyListeners` は listener 例外を捕捉せず後続が呼ばれない

### A7 プレイリスト rename 時の既定シャッフル移行の扱い
- `server/app_collection_shuffle.go` `renamePlaylistShufflePreference`
- 新名側に既存の既定があると無言で上書き。値が "on"/"off" 以外だと旧キーだけ消して設定消失。キー生成が未加工の newName で、実体の TrimSpace 済み名前とずれて既定が孤児化しうる

### A8 RenamePlaylist バインディングの無検査型アサーション
- `server/app_playlist.go`: `data["oldName"].(string)` 等が欠落/型違いで panic しうる

### B4 GetLyrics の探索キーが経路で不一致（title のみ vs ファイル名優先）
- `src/renderer/js/core/bridge.ts` は title のみ、`env-setup.ts` はファイル名→title の順。「ファイル名≠タイトル」の曲で title 経路が常時ミスする（現状は潜在的不整合）

### B5 FindLyrics のエラー握りつぶしと.ja フォールバック不全
- `internal/lyrics/lyrics.go`: 読み取り失敗を「なし」として進む。ja.lrc の失敗時に ja.txt を試さず即 return

### B6 CopyLyricsFiles は拡張子フィルタなしで任意ファイルをコピー・同名上書き
- `internal/lyrics/lyrics.go`（SaveLrcFile 側には許可リストがあるのに対照的）

### B7 mergePlainTxtWithJa: 和訳側の行数が多いと空白行が末尾に増える
- `src/renderer/js/features/lyrics-translation.ts`: 行数を `Math.max(en, ja)` で決めるため、主歌詞のない行が追加される
