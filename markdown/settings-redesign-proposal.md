# 設定画面 再設計提案（要議論）

作成日: 2026-08-23 / 対象: Desktop（Wails）

## 現状の問題
- `index.html` 255〜720行目の単一モーダルに 14 グループが縦一列に並び、タブもナビゲーションもない
- 保存契約が「OK押下で全項目を一括保存」（`init-settings.ts` 769行目〜）。一方でデバイス可視性・UX Sync ストレージ・歌詞同期モデル同意は各自即時保存しており、混在している
- グラフィックEQ（10バンド）だけが設定モーダル内、簡易EQ（Bass/Mid/Treble）が右サイドバーにあり、同じ `state.equalizerSettings` を2つの UI が別々に描画している
- UX Sync サブモーダル（721〜804行目）だけがタブ構造を持っている

## 提案: サイドナビ付き設定ページ（モーダル廃止）

```
┌─────────────┬──────────────────────────────┐
│ 一般         │  （選択中セクションの内容）    │
│ 再生・オーディオ│                              │
│ ライブラリ    │   項目は即時保存（OKボタン廃止）│
│ 外観         │                              │
│ YouTube      │                              │
│ 連携（Mobile/Sync）│                          │
│ AI 機能 (Beta)│                              │
│ 詳細・ライセンス│                              │
└─────────────┴──────────────────────────────┘
```

| セクション | 収容する既存グループ |
| --- | --- |
| 一般 | UIテーマ以外の「その他」項目、グリッド表示密度（今回追加） |
| 再生・オーディオ | オーディオデバイス、**EQ（統合後の単一UI）**、ダウンロード品質 |
| ライブラリ | インポートモード、CDリッピングモード |
| 外観 | UIテーマ、ビジュアライザーモード |
| YouTube | YouTube再生モード |
| 連携 | モバイル連携（QR）、UX Sync（既存タブ構造をそのまま内包） |
| AI 機能 | AI音声解析、歌詞自動同期モデル、スコア有効期間 |
| 詳細 | ライセンス情報、診断（pprof など） |

### 保存モデル
- 各コントロールが変更時に `saveSettings({ key })` を即時呼び出す（バックエンド `SaveSettings` は shallow merge なので追加変更不要）
- 「OK / キャンセル」を廃止し「閉じる」のみ。破壊的操作（キャッシュ削除など）だけ確認ダイアログ
- 実装は設定ページを `js/ui/settings/` 配下にセクション単位のモジュールへ分割（現在の 800 行超の `init-settings.ts` を解体）

### 見た目
- 右クリックメニュー再設計と同じ原則: テキストで誤魔化さない（トグルは実スイッチ、選択はセグメント/セレクト、アイコンは SVG）
- 検索ボックス（項目名フィルタ）を左ナビ上部に

## EQ の非対称性について（判断を仰ぎたい）

現状: 右サイドバー=3バンド簡易、設定=10バンド曲線。どちらも同じ state を更新するため、片方で動かすともう片方の表示が「間接的に」変わる（3バンド→10バンドは変換、逆は不可逆）。

選択肢:
1. **A. 右サイドバーに一本化**（推奨）— 10バンド曲線エディタをサイドバー幅に合わせてリサイズ可能にし、プリセット＋ON/OFF＋リセットを同居。設定画面からは EQ を撤去し「EQ はプレイヤーパネルから」のリンクのみ。再生中に触る機能なので再生画面側にあるべき、という整理。
2. B. 設定画面に一本化 — サイドバーは ON/OFF とプリセット選択だけの「リモコン」に縮退。
3. C. 現状維持で同期表示だけ整える（3バンドを10バンドの「サマリー」として表示し、10バンドを編集した後は3バンドスライダーを無効化して「カスタム」と表示）。

A を選ぶ場合、サイドバー EQ タブの「領域の使い方が適当」問題も同時に解消できます（曲線エディタがタブ全面を使う）。
