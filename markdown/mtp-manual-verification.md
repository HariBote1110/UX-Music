# MTP 実機検証手順書（libkalam FFI 廃止後）

対象: `refactor/mtp-direct-gomtpfs` ブランチ以降の MTP 実装（go-mtpfs 直接 import 版）。
MTP はユニットテストではフェイクデバイスまでしか担保できない。以下は**実機の Walkman を USB 接続した人間にしか確認できない項目**の手順である。「動くはず」で終わらせず、各項目に結果（OK/NG と気付き）を記入して残すこと。

## ユニットテストで担保済みの範囲（実機では再確認不要）

- パス文字列 → コンポーネント分解、パス → オブジェクトハンドル解決の論理
- Walk の一覧整形（`name`/`path`/`size`/`isFolder`/`date` の JSON 形状、隠しファイルスキップ、再帰）
- MakeDirectory の find-or-create（既存ディレクトリで no-op）論理
- 転送進捗コールバック → `TransferProgress` への写像
- ストレージ情報・デバイス情報のマップ形状（`mtpDeviceInfo.Model` 等）

## 実機でしか確認できない範囲

ユニットテストが担保しないのは「本物の Walkman が MTP プロトコル上でどう振る舞うか」と「libusb / USB スタックとの相互作用」。具体的には以下。

### 準備

1. `wails dev` または `make`（開発ビルド）でアプリを起動する。
2. Walkman を USB 接続し、Walkman 側で「USB 接続モード: MTP（ファイル転送）」を選ぶ。

### 1. 検出・接続（ポーリングモニタ）

- [ ] 接続後 5〜60 秒以内に UI にデバイスが現れる（`mtp-device-connected` イベント）。
- [ ] デバイス名が「MTP Device」ではなく実際のモデル名（例: NW-A306）で表示される。
- [ ] ストレージ一覧に本体メモリ（＋microSD 挿入時は 2 つ目）が出て、空き容量・総容量が Walkman 本体の表示とおおむね一致する。
- [ ] **抜き差し**: ケーブルを抜いて `mtp-device-disconnected` が発火し UI から消える → 再接続で再び検出される。これを 3 回繰り返しても検出が壊れない（Dispose → Initialize の再初期化経路の確認）。
- [ ] アプリを起動したまま 10 分放置してもログが stderr スパムで溢れない（旧実装の LIBUSB_ERROR 汚染が再発していないこと）。アプリ自身のログ（[MTP Monitor] 等）が**消えていない**ことも確認（旧 stderr ハックはプロセス全体の fd 2 を握り潰していた）。

### 2. ブラウズ（Walk）

- [ ] MTP ブラウザでルート → /MUSIC（または /Music）へ辿れる。フォルダが先・ファイルが後で名前順に並ぶ。
- [ ] 日本語ファイル名（NFC/NFD 混在があり得る）・全角記号を含む名前が文字化けせず表示される。
- [ ] 数百ファイル入りのフォルダを開いて数秒以内に一覧が出る（旧 JSON 往復比の体感でよい。後の案2の基準値として所要時間をメモする）。
- [ ] 存在しないパスを開いたときにクラッシュせずエラー表示になる。

### 3. アップロード（最重要・Walkman 固有の作法）

- [ ] 楽曲 1 曲（FLAC と MP3 の両方）を転送 → 進捗バーが 0→100% まで動く（`mtp-upload-progress`）。
- [ ] `MTPUploadFilesWithStructure` 経由（同期画面からの転送）で「アーティスト/アルバム」の階層が**なかった場合に自動作成**されて転送される。
- [ ] 既存と同名ディレクトリへの転送で重複ディレクトリが増えない（find-or-create の実機確認)。
- [ ] 転送後、**Walkman を USB から外した後に Walkman 側のライブラリに曲が現れ、最後まで再生できる**（サイズ 0 や途切れは SendObjectInfo のサイズ不一致バグの兆候）。データベース再構築が走る機種では完了まで待つ。
- [ ] 数十曲（1GB 規模）の一括転送が完走する。途中でケーブルを抜いた場合にアプリがクラッシュせずエラーになる（中断・再開の実装は案2スコープ。ここではクラッシュしないことだけ確認）。

### 4. ダウンロード

- [ ] デバイス上の曲を 1 曲ローカルへダウンロードし、バイト数が一致・再生可能。

### 5. 削除・ディレクトリ作成

- [ ] ファイル 1 つを削除 → ブラウザ再読込で消えている。Walkman 側ライブラリからも消える。
- [ ] 空でないフォルダの削除がどう振る舞うか記録する（機種依存: MTP の DeleteObject は再帰削除する機種としない機種がある）。
- [ ] 新規フォルダ作成 → 実機のファイラ（PC の Finder 等ではなくアプリの再 Walk）で見える。

### 6. 未転送曲の検出（MTPGetUntransferredSongs）

- [ ] ライブラリと Walkman の差分検出が完走し、実際に転送済みの曲が「未転送」と誤判定されない（NFC/NFD・全角半角の正規化が実機ファイル名で機能しているか）。

### 7. 配布ビルド

旧実装は配布 .app に libkalam.dylib を同梱しておらず、**配布版の MTP はそもそも動いていなかった可能性が高い**（scripts/build-install-app.sh に dylib 処理なし）。今回から libusb を Frameworks に同梱し install_name_tool で付け替えるため、ここは新規の検証項目:

- [ ] `scripts/build-install-app.sh` で作った .app を **Homebrew の libusb が無い状態を模して**起動する: `DYLD_PRINT_LIBRARIES=1` で起動しログの libusb-1.0.0.dylib のパスが `.app/Contents/Frameworks/` を指すこと（`otool -L UX-Music.app/Contents/MacOS/UX-Music` でも確認可）。
- [ ] その .app（署名済み）で上記 1〜3 の最小セット（検出→ブラウズ→1曲転送→実機再生）が通る。
- [ ] Gatekeeper: 署名後の .app で MTP 接続時にクラッシュしない（cgo + 同梱 dylib の署名漏れがあるとここで落ちる）。

### 8. Windows（配布前提が立ったときに）

Windows は CI でコンパイルが通ることのみ担保。実行時は WinUSB/libusb ドライバ構成に依存するため、Windows 実機 + Walkman での検出確認は別途必要（本手順書の 1〜3 を Windows で再実施）。現時点では未検証と明記しておく。
