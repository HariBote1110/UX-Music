# 発生していた再生関連のバグと修正内容

調査の結果、以下の2つの主要なバグ（エッジケース）が発見され、修正を行いました。

## 1. シーク中のデータ競合・デッドロックによる音声の乱れ・パニック（Go Backend）
- **事象**: 再生中の楽曲に対して短い間隔でシークバーを操作すると、デコーダが古いデータを読み込んでしまい、音声バッファに混ざる（再生が乱れる・ノイズが入る）現象や、一時停止/再生とシークが競合した際にデッドロックでフリーズする問題が内在していました。
- **原因**: 
  1. `decoderLoop()` 内で `decoder.Read()` を呼び出す際にロック（`p.mu`）を獲得し直していなかったため、非同期に行われる `Seek()` 操作（ファイルポインタの移動）と読み込みが並行して実行されてしまい、競合が発生していました。
  2. `Play()` 実行時、デコーダを停止する `p.decoderStop` のクローズ処理を行う前に `mu.Lock()` を獲得していたため、すでに `decoderLoop()` が `RLock()` を待っている場合などにタイミングによってデッドロックに陥っていました。
- **修正内容**:
  - `Play()` におけるデコーダループ終了処理を `mu.Lock()` の外側に移動し、デッドロックを防止。
  - `decoderLoop()` の処理内で `decoder.Read()` とリングバッファへの書き込み全体を `p.mu.RLock()` で保護するようにスコープを拡大し、データ競合とそれに伴う音声の乱れを解消しました。

## 2. 特殊文字を含むパスでの再生不可（Web Player）
- **事象**: `%` や `?` などの特定の記号がファイル名やディレクトリ名に含まれていると、ローカルプレイヤー（Web `Audio` 制御時）で再生ができない（サイレントに失敗する）エッジケースがありました。
- **原因**:
  - パスのエンコードに `encodeURI()` が使用されていましたが、`?` などはURIの予約語と見なされてエスケープされず、ブラウザ側でクエリパラメータとして誤認されるため、ファイルが見つからない（またはMIMEが壊れる）状態になっていました。
- **修正内容**:
  - `song.path.replace(/\\/g, '/').split('/').map(encodeURIComponent).join('/')` とすることで、パスの各コンポーネント（ディレクトリやファイル名）ごとに正確に `encodeURIComponent` を適用し、特殊記号がパスクエリとして解釈されないよう修正しました。
