# 低音オンセット検出器の設計

## 目的

iPhone で Watch 転送時に曲のキック／ベースの立ち上がりを検出し、Watch で再生時刻に対応する
離散触覚を鳴らすための時刻列を作る。検出器は AVFoundation から分離し、決定的な Float32 配列を
入力する純粋な DSP としてテスト可能にする。

## 採用したパラメータ

- 入力は Builder が mono Float32、22,050 Hz に変換する。
- FFT フレームは 2,048 サンプル（約 92.9 ms）、ホップは 512 サンプル（約 23.2 ms）。
  23 ms 程度の時間分解能なら、実機結果の 125 ms 間隔の触覚を十分に区別でき、低音の周期を
  60 Hz 付近まで安定して観測できる。ホップを細かくする代わりに、検出したフレームの中心を
  raw samples の RMS 包絡を調べるためのアンカーとして使い、立ち上がり時刻をサンプル位置へ
  再整列する。
- Hann 窓を適用し、30〜150 Hz の bin エネルギーだけを合計する。これはキックの基音と低い
  ベースを残し、6〜10 kHz のハイハットを構造的に除外する帯域として選んだ。
- 各フレームの帯域エネルギーを `log1p` 圧縮し、前フレームとの差分の正値だけを spectral flux
  とする。立ち上がりに反応し、持続音や減衰には連続発火しにくい。
- さらに帯域エネルギーがフレーム全体の 5% 未満の候補を捨てる。これは合成検証で確認した
  ハイハット様の高域ノイズが FFT 漏れだけで flux 閾値を超えるケースを除外するためである。
- 閾値は前後約 1 秒の local median + 3 × MAD とし、全体最大 flux の 8% を下限にする。
  MAD は局所的な音量変化に追随し、8% の下限は定常ノイズの小さな揺らぎをオンセットにしない
  ための安全網である。
- flux の局所最大だけを候補にし、候補を強度の大きい順に選びながら 125 ms 未満の候補を
  抑制する。近接したピークでは強い方を残し、最後に時刻順へ戻す。
- 強度は採用ピークの最大値で割り、0〜1 に正規化する。

## 時刻精度の測定

`watch_haptics_research/tools/onset-timing-harness/` の macOS ハーネスで、XCTest の
`bassBursts(at:)` と同じ 60 Hz・80 ms・8 ms attack・linear release の信号を生成した。
基準の 0.5〜4.5 秒列に加え、全オンセットを +7 ms、+13 ms した位相も測定した。処理時間は
22,050 Hz の 30 秒信号を `swiftc -O` で一度検出した時間である。

| 試行 | 変更 | max|error|（0 ms / +7 ms / +13 ms） | 他4テスト | 30秒処理 |
| --- | --- | ---: | --- | ---: |
| baseline | frame start + frameSize/2 を報告 | 29.388 / 33.304 / 31.549 ms | PASS（基準テストは一部 FAIL） | 4.71 ms |
| 1 | flux 局所ピークの放物線補間 | 24.548 / 24.455 / 24.701 ms | PASS | 4.71 ms |
| 2 | 放物線補間を戻し、hop だけ 512→256 | 35.601 / 35.617 / 31.549 ms | PASS（基準時刻テストのみ FAIL） | 7.72 ms |
| 3 | 512 hop のまま raw RMS 包絡で再整列 | 4.263 / 4.247 / 4.234 ms | PASS | 5.59 ms |
| 4（採用） | RMS を明示的に計算し、閾値を RMS peak の 50% に設定 | 2.449 / 2.433 / 2.420 ms | PASS | 5.31 ms（再確認 5.46 ms） |

採用パラメータは、FFT 2,048 サンプル、hop 512 サンプル、探索半径 ±50 ms、RMS 窓 2 ms、
局所 RMS peak の 50% crossing である。30 秒処理は baseline の約 1.13〜1.16 倍で、2 倍以内に収まる。
RMS 包絡が作れない境界ケースでは、従来のフレーム中心推定へフォールバックする。

## 長い音源の扱い

AVAssetReader は 30 秒チャンク、1 秒オーバーラップで読み、チャンクごとの結果を 125 ms ルール
でマージする。10 分音源でも解析用の配列は最大約 31 秒分に留まり、全曲を Float32 配列へ保持
しない。チャンク境界のオンセットを取りこぼさないためにオーバーラップを設けた。

## 既知の制約

これは「低音の立ち上がり」を検出する軽量なヒューリスティックであり、音楽的な拍・小節や複数の
ベース音の分離を保証するものではない。Watch 側の最小発火間隔は実機結果から 125 ms とし、
検出器も同じ値を共有モデルの `minimumOnsetGap` として使う。

## 追記

解析は曲ごとの detached タスクを並列起動せず、utility 優先の単一シリアル worker に集約する。
転送単位と一括処理は同じ worker を共有し、同じ song id が待機中なら一度だけ構築する。また Watch
は `watchLibrarySongIds` を application context で報告するため、一括処理ではその最新ライブラリを
優先し、iPhone 側の完了履歴だけに残る削除済み曲を再送しない。
